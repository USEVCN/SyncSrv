# Linux / macOS 监听与并发排查

本轮代码面向 **0.15.0-dev 待统一打包发布**；本报告记录源码与隔离测试结果，不代表已有客户端升级完成。

## 已确认并修复

| 平台 | 问题与证据 | 修复 |
| --- | --- | --- |
| Linux / 使用 Linux Agent 的 NAS | 原 inotify 接收循环在新目录到达时同步递归 WalkDir。移入大目录会推迟其它目录事件消费。新增阻塞注册用例证明接收隔离。 | 新目录递归注册交给 4 个有界后台工作协程；事件接收及时入队，注册完成后补发范围变化，覆盖注册前子目录事件窗口。队列满明确要求校准。 |
| Linux | 目录重命名后，已有深层目录仍绑定旧路径；在真实 Linux 中连续 5 次复现 `missing native notification job:renamed/nested/deep/alive.txt`。 | 按设备号和 inode 识别目录，在新的路径登记前解除旧绑定；后台移除已删除目录的 watch。 |
| Linux | 快速重命名、删除、同名重建时出现 `invalid argument`，或旧清理任务错误移除新目录监听。25 轮测试暴露了单次未出现的竞争。 | 内核已经移除的 watch 用持久化 OVERFLOW 通知和覆盖重建恢复；清理前核对当前目录 inode，保留已经登记的新目录；注册期间再次到达的事件保留下一轮注册请求。 |
| macOS | 父 context 取消会先退出事件消费者；原生 FSEvents 回调仍向有界通道发送，停止时可能等待；`MustScanSubDirs` 没有明确触发完整校准。 | 停止原生流期间继续消费回调，再结束并等待消费者退出；合并目录事件明确提交 RESCAN，丢失、卸载和根变化仍提交 OVERFLOW 并报告异常。 |

Linux 的 watch 元数据变更保留短互斥区，接收侧查询不持有该锁，避免与 fsnotify 内部发送/注册锁形成等待。文件读写、归档和网络传输不在该互斥区中。目录删除的旧事件不会强制拆除已重建的同名目录。

## 实际测试

- **macOS ARM64 本机**：全部 Agent `go test -race -count=1 ./...` 通过，17.040 秒；原生 FSEvents、多根隔离、移动后的深层文件监听、删除重建和负载下停止测试连续 5 轮通过，10.762 秒。合并事件标志使用构造事件测试；没有通过填满操作系统事件队列来伪造丢失。
- **Linux ARM64 实际内核**：复用已有 OrbStack Docker，不创建新 VM；本地已有 `eclipse-temurin:8-jre-jammy` 镜像，容器断网、根文件系统只读、只有临时测试目录，未挂载业务目录。测试二进制先交叉编译，再在 Linux 容器实际执行。
- Linux 普通用户 UID 65534 执行完整测试：**76 组顶层测试通过，0 跳过、0 失败**。先前 root 容器因绕过文件权限跳过的两组用例，已在普通用户下补测通过。
- Linux 原生监听用例连续 **25 轮**通过；包含递归注册阻塞时其它根仍及时收到事件、取消正在注册的目录、移动后的深层文件、删除重建、根重命名及重复停止。
- Linux 同时验证本轮通用并行流水线：4 个独立设备命令并行、同路径和限速冲突隔离、取消等待写入结束、旧中心兼容、真实四文件 COPY 与持久化回执、进度 HTTP 不锁其它文件工作协程，全部通过。最终全量还包含 SFTP 请求并行、SHA 一致性、失败后清理并续传、取消排空和限速不倍增。
- `scripts/test-agent-management.py` 的 **13 组**服务管理模拟测试通过。模拟覆盖 systemd 升级/回滚、启动停止、管理互斥、卸载保留身份与队列、旧服务名和 macOS 卸载。
- 所有临时测试容器均使用 `--rm`，完成后没有留下测试容器。没有注册、停止或卸载本机系统服务，没有读取或修改实际备份目录。

## 仍需部署环境验收

- **Linux x64 原生机器、群晖 DSM / 其它 NAS 实机**尚未执行本轮安装、服务重启与 源目录 → 备份库→归档库性能验收。ARM64 Linux 容器结果不能替代这些边界；本轮未运行 Linux race 检测器，race 检查是在 macOS 本机执行。
- macOS 已测试真实文件事件与 common 逻辑，但没有修改或注册系统 LaunchDaemon；systemd、launchd 的安装、卸载仅模拟验证。
- 初次启动/重新配置时仍要完整登记现有 Linux 目录，建立完整覆盖后才返回；这段可能受目录数、磁盘和 inotify 配额影响。运行期的新目录注册已独立，不应将首次登记耗时等同于数据传输单线程。
- Linux 网络/FUSE 挂载与 macOS 非本地卷继续拒绝原生监听；应把 Agent 安装到存储主机，避免把挂载卷当作有可靠原生事件的本地盘。
- 没有自动修改 inotify 配额或系统资源上限；实际大目录树仍需确认 NAS 配额和服务账户读取权限。本报告不承诺任何 NAS 端到端吞吐数字。
- 本轮未改变 `SyncSrvAgent` 服务名称、手工运行 update 升级策略，以及身份、队列、日志和备份文件保留规则。
