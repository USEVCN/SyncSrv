# 源端并发与快速启动 · 0.12.0-dev

## 本次行为

针对文件源 A 的 Agent 直传实时备份 B：

- 编辑备份任务，可设置「并发文件数（线程数）」1–16，默认 4；1 为串行。保存后下一批执行使用新配置。不同任务独立保存。
- 原流程先读取整批文件并计算全部 SHA-256，之后才开始传输。现在先读取目录、大小、修改时间等元数据，提前显示待处理文件；多个工作线程分别计算当前文件校验值、传输、回读校验，完成一个就继续下一个。
- 不需要等整批文件全部校验完才传第一个文件。首次或补扫仍需枚举相应目录；每个文件传输前仍要计算自己的 SHA-256，超大单文件的首读时间不能消除。
- 每个工作线程复用自己的协议连接；本地、SMB、SFTP、FTP、WebDAV 使用相同工作池。任务限速在本批所有并发文件间共享，包含目标回读校验流量，本地源文件计算校验值不占网络限速。
- 文件列表支持同时显示多个执行中文件的阶段、传输进度及校验进度。总览每秒采样累计传输与校验速度，数据量按逻辑文件大小计数，完成数只在收到有效内容回执后增加。

本设置作用于 A → B 源端传输。服务端归档、恢复与快照提交仍按既有依赖顺序执行；0.11 的设备本地执行能力继续保留。本次不代表所有阶段都已并行，也不是同一大文件拆成多段同时上传。

## 完整性与失败处理

发现清单只用于进度显示，不写入已验证清单，不可发布基线或触发删除。每个文件完成预校验后才登记其内容哈希，传输后按已有机制回读验证 B。整批所有工作线程结束、内容回执齐全后才提交。

一个文件失败或任务取消时，停止派发并取消其他线程，等待所有本地写入线程退出后才中止会话，避免重试与上一批同时写入。未确认的变化留在原有队列。已有基线时仍可按原有规则重试独立变化范围；首次或全量范围仍须完整成功。源文件修改、读取失败均不可当作删除。

多个线程同时创建同一个目标父目录时，创建失败会重新检查实际目录；已被另一线程创建的真实目录可继续，文件或符号链接仍被拒绝。

## 使用步骤

1. 等当前备份结束或暂停，在 IDEA 重新运行服务端，使新配置、发现清单及多文件进度接口生效。前端重新加载。
2. 在「备份设备」下载安装包 0.12.0-dev。Windows 解压后，以管理员身份运行 `update.bat`，选择现有安装目录（例如 `E:\SyncSrv`），保留现有身份和运行数据；不需要重新配对。
3. 网页确认设备上报版本为 0.12.0-dev，在任务中设置并发数，下一批检查文件列表中的多个执行中状态。

新源端依赖本版中心的发现清单接口；请先升级中心再更新源端。旧源端可继续连接新中心，但仍按原串行流程运行。不同设备、磁盘及网络条件下的最佳并发数需要实测，增大并发数不保证线性提速。

## 验证范围

自动化测试使用真实本地目标文件 I/O、模拟控制接口，验证三个文件同时进入传输流程、独立内容校验、所有内容回执齐全后才能完成、后续文件无法读取时首个文件仍已开始传输且整批不误提交。另验证共享限速、失败取消并等待所有线程、并发目录创建、独立进度与重复采样、清单不能单独发布基线。

本机初始化微基准：32 个文件、每个 1 MiB，Apple M4 Pro/macOS，运行 3 次；原整批预读 SHA-256 平均 15.02 ms，元数据清单平均 0.145 ms。该数据仅衡量本机初始化步骤，使用缓存中的小测试数据，不是 Windows → 群晖实机启动耗时或网络吞吐保证。

Windows 服务与群晖 SMB 的实际并发速度、CPU、内存和网络利用率仍需在更新后实测。本次未中断现有实机备份、未自动升级远端设备。
