# SyncSrv 研发、部署与升级

发行服务器：RelsHub，项目 `syncsrv`。中心 Linux x64；Agent 仍为 0.16.0 八平台包。H2/现有命名与界面保持不变。完整安装包不包含正式数据、账号密码或发布私钥。

## 研发与验证

在隔离构建目录执行，避免替换 IDEA 运行中的 target/classes 或静态页面：

```sh
sh scripts/build.sh
python3 scripts/test-release-source.py
python3 scripts/test-center-update.py
python3 scripts/test-interactive-installer.py
(cd Backend && mvn test)
(cd Frontend && npm test)
```

构建门禁将源码、已编译静态页面和精确 JAR 哈希绑定。完成实际回归后生成验证收据，再运行 scripts/package-linux.py；收据超过 24 小时或源码/JAR 不符会拒绝打包。运行时从 runtime.lock.json 校验，不能使用未知 JRE。

## 发布权限与公钥

Mac 首次执行，隐藏输入现有 RelsHub 管理员密码：

```sh
sh scripts/publish-relshub.sh setup --url http://192.168.50.118:18760 --allow-http-origin http://192.168.50.118:18760
sh scripts/publish-relshub.sh status
```

管理员会话只用于获取当前项目 READ/UPLOAD/PUBLISH/CHANNEL 的 90 天令牌，令牌存 macOS 钥匙串；配置与回执保存在 work/relshub。过期后重新 setup。令牌绑定站点与项目，修改地址不能复用旧凭据。

RelsHub 运维仅登记 `syncsrv-2026.pub` 公钥到实际 trusted-keys 根目录下 `syncsrv/syncsrv-2026.pub`。发布私钥保留在构建机 config/release-signing-private.pem，权限 0600，单独加密备份。不要上传私钥，不替换已登记的不同公钥。

## 发布

显式发布已经测试的包；日常编译不会自动上传，也不会启停客户端：

```sh
sh scripts/publish-relshub.sh publish --package dist/syncsrv-0.4.3-linux-x64.tar.gz --notes docs/发行说明-0.4.3.md --from-version 0.4.0 --source-max 0.4.2
```

先上传完整包，再上传固定原生信任签署的 syncsrv-center-release.json；本地逐字段核对 RelsHub canonical 计划后签名发布，再按 revision 切换 stable。未知网络结果用相同参数重试，不能改包覆盖已发布版本。--register-only 只登记不推荐；私有 beta 需要额外客户端授权，本次部署使用公开 stable。

## 新服务器安装

先通过可信交付或 RelsHub 下载完整包并核对 .sha256 与签名证据，再解压：

```sh
tar -xzf syncsrv-0.4.3-linux-x64.tar.gz
cd syncsrv-0.4.3-linux-x64
sudo sh install.sh --update-manifest 'http://192.168.50.118:18760/api/v1/projects/syncsrv/channels/stable/manifest?os=linux&arch=x64' --allow-http-origin http://192.168.50.118:18760
```

需要 systemd、Python 3.9+ 和 Linux x64；无需安装系统 Java。程序 /opt/syncsrv/releases，原子指针 /opt/syncsrv/current，配置 /etc/syncsrv，数据 /var/lib/syncsrv。安装器遇到已有目录拒绝覆盖，不自动启用尚未配置的服务。

在 /etc/syncsrv/application-private.yml 配置独立 HTTPS 审计锚点，syncsrv.env 填首次管理员密码及监听地址。默认 127.0.0.1:18010，通过反向代理访问；需要直接内网访问时由运维设置明确监听地址。先运行 initialize.sh 登记审计公钥，再 systemctl enable --now syncsrv。生产要求审计锚点，不能为启动成功而关闭该要求。

## 日常升级与恢复

```sh
sudo sh /opt/syncsrv/current/update.sh check
sudo sh /opt/syncsrv/current/update.sh update
sudo sh /opt/syncsrv/current/update.sh recover
sudo sh /opt/syncsrv/current/update.sh rollback
systemctl status syncsrv
journalctl -u syncsrv -f
```

更新源一次保存在 /etc/syncsrv/update.json，由 root 管理。HTTP 仅限显式配置的确切内网 IP/端口，禁止重定向；跨网必须 HTTPS。不从 RelsHub 获取或执行运维命令。

先验签和校验完整包，预留空间，验证包内 JVM，再停止服务、原子切换、启动及检查数据库/版本健康。失败切回前一版本；中断先 recover。升级阶段写入 /opt/syncsrv/upgrade-state.json；原生签名清单、包哈希和阶段历史保存在 /opt/syncsrv/upgrade-evidence（root 管理）；旧版本保留。这些运行记录不等同于独立外部审计锚点。schema 变化或版本不在已签署来源范围时拒绝自动升级。

已有 0.4.0 首次接入：可信解压 0.4.2 包，使用其中 update.sh 传入 --manifest 和必要的 --allow-http-origin，仍以已安装 0.4.0 JAR 的固定公钥验签。0.3 不能直接走此自动链路，应按 Linux安装包.md 完成旧布局迁移，并保留整套停机备份。

升级前应停机形成 H2、密钥、配置和 B/C 文件卷的一致备份。程序失败回滚不是数据库任意降级，也不能替代灾备。

## 卸载与验收

uninstall.sh 只停止并注销中心服务，保留程序、配置、H2、密钥和所有备份文件。Agent 的 install/update/uninstall 与中心分开，Linux 服务名 SyncSrvAgent。

每次交付留存源码/JAR/包哈希、发布回执、渠道 revision、匿名下载校验、运行版本和升级事务状态。测试环境、容器、仿真与真实 NAS/宿主 systemd 结果分别记录；只有包验证不代表完成正式部署。

## 192.168.50.118 内网验证实例

2026-10-23 已完成真实 systemd 的 0.4.1 → 0.4.2 → 0.4.1 → 0.4.2 安装、升级、回滚及再次升级，启用开机启动；使用包内 Java，H2 健康。此实例明确使用非生产模式，仅绑定 192.168.50.118:18010，未迁移正式数据。首次升级后的密钥与 syncsrv.env 已逐一比对一致。独立 HTTPS 审计锚点仍属于正式上线前置项。

此实例的健康检查地址是明确内网 IP，升级、回滚、恢复均须传入对应参数：

```sh
sudo sh /opt/syncsrv/current/update.sh check --health-url http://192.168.50.118:18010/api/health
sudo sh /opt/syncsrv/current/update.sh update --health-url http://192.168.50.118:18010/api/health
sudo sh /opt/syncsrv/current/update.sh rollback --health-url http://192.168.50.118:18010/api/health
```

0.4.3 修复入口缓存策略。浏览器若已经缓存 0.4.1/0.4.2 的入口，首次访问请使用 `http://192.168.50.118:18010/?v=0.4.3` 或强制刷新；新入口使用 no-store，带内容哈希的脚本及样式继续允许缓存。
